# Improve run, 2026-10-20

Branch `improve/auto-2026-10-19`, from `main` at `53f7f3e` (2.0.0). Ten
read-only analysis agents (security, correctness, tests, docs, UI in a
browser, design, refactor, performance, a11y, config), then triage: high and
medium fixed, low left alone on purpose. Both test suites (Odoo 19 and 20)
were green before and after each iteration.

## Iteration 1

**Chat window**
- The bus payload now carries `channel_id`, so Stop shows while a run is
  live (`runtime/stream.py`, `static/src/chat/run_events.js`).
- A reload no longer loses a waiting approval: the thread asks
  `pan_ai_state` when an AI channel opens and rebuilds the card and Stop
  (`static/src/chat/thread_patch.js`, `run_events.hydrate`).
- Switch agent opens: the picker is a static import (Odoo's bundler has no
  dynamic import) (`static/src/chat/thread_actions.js`).
- Odoo's channel actions that mean nothing in a one-person agent chat
  (invite, favourites, mute, recordings, hide, pin, rename, leave) are
  hidden on `ai` channels.
- Action icons carry a Font Awesome name for Odoo 19 (`compat.actionIcon`).
- Stop on a waiting approval, or the stuck cron, writes the final body and
  tells the window (`stream.finish_outside`), so no card or "Thinking" stays.
- a11y: the stream is `aria-live`, the approval group and buttons are
  labelled, the error is `role="alert"`. The approval card's border is
  amber (a status), not the accent (`docs/brand.md` updated).

**Runtime**
- Stop between a tool call and its result, or on a waiting approval, closes
  the open calls with "Stopped by the user." so the next message works
  (`slices.close_open_calls`, `thread._close_open_calls`).
- The heartbeat beats on a clock (every 10 s) while the model is silent;
  a claim goes stale after 45 s, not 30 (`slices.heartbeat`, `run.STALE_SECONDS`).
- A tool that fails at the database (foreign key, missing value) runs in a
  savepoint and returns the error to the model instead of aborting the run.
- The agent's `time_limit` is enforced in the slice loop, on the time
  worked in slices (`worked_seconds`), not on the clock: waiting in the
  queue or for an approval does not count.
- A thread keeps its last 60 messages, cut at a user prompt; a continuous
  thread that hits a limit pauses instead of failing every tick.
- The cron budget accounts for the slice it starts; `limit_time_real_cron`
  -1 means `limit_time_real` (Odoo's rule) and 0 means the default of
  120 s, not 10 s (`slices.server_limit`).
- The hourly cap refuses what a person starts by hand (a chat, a Fill
  button) and counts their chats and triggered runs; a watch's ticks, a
  schedule and the nightly fills are the administrator's settings and are
  never refused. A tick creates its run and leaves it to the budgeted
  worker loop; it moves its cursor only after the run started.
- The claim fence compares Python UTC timestamps, not the database's
  session-time `now()`.
- `_after` survives a record that refuses the note or the activity; the run
  says so in `error`.
- Triggered runs (an automation in somebody's request) go to the worker
  crons whole; the person's transaction is theirs. Scheduled runs are
  unchanged.
- `pan_ai.run.error_code` (limit, model, timeout, build, access, unresolved,
  stuck, other); the heartbeat counts those, never the error text.

**AI fields**
- `pan_ai_fill` is guarded: internal users only, write access on the
  records, at most 50 at once, the agent's own checks.
- Fill now queues the cron (`pan_ai.fill_now`), one batch per wake, instead
  of up to 200 model calls in the button's request.
- A record the run user may not write, or that failed, is recorded and left
  alone for a day, so a batch rotates through the table.
- `pan_ai_fields_of` is an ormcache per model, cleared when a prompt changes
  (every write on every model asks it).
- The Enterprise seam's write of the prompt is explicitly sudo.

**Platform client**
- The platform URL override must be https (http on this machine only) and
  is logged on every use; redirects are never followed.
- One refusal message per state (pending, revoked, refused, no plan, lapsed).

**Defaults, settings, docs, CI**
- `defaults.py` holds the four defaults Settings and the code shared.
- Settings: titles back on the four inputs, Remove key in the Danger zone,
  "Delete all threads". Runs: duration in seconds, a display name.
- The default agent is "Odoo agent" on a fresh install; an upgraded
  install keeps the name it has (the record is `noupdate`).
- `ARCHITECTURE.md` points at `docs/architecture-20.md`; the architecture,
  plan, protocol and execution plan say what shipped (plain key by decision
  16, one live run per thread, error codes, no code execution).
- CI runs on branches with a slash; `no_em_dash.py` scans views, data and
  the chat bundle; `cryptography>=45` pinned beside pyOpenSSL.

**Left alone (low, or needs a human)**
- Low findings of every agent (about 50).
- `static/description/banner.png` is a placeholder: the banner is a brand
  asset to render in the brand repo.
- A Discuss sidebar category for AI chats: a design choice; "Open in
  Discuss" still lands with an empty sidebar.
- OpenRouter key and MCP tokens stay plain (decision 16); the docs now say
  so instead of promising encryption.
- The Enterprise 20 seam is still unmeasured on a real Enterprise.
